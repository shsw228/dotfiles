# Notes Vault Routing Rules

## Root

`~/Developer/ghq/github.com/upft-kengotate/Notes`

## Folder Selection Guide

### `03.Projects/`

Use this for anything clearly tied to one project or one workstream.

Good examples:

- app-specific architecture notes
- bug investigations
- implementation summaries
- vendor response summaries
- debugging logs and conclusions
- rollout notes

### `02-Resources/`

Use this when the content should be reusable without caring which repository it came from.

Good examples:

- SDK API summaries
- command references
- reusable setup instructions
- troubleshooting checklists

### `04.Research/`

Use this for multi-project or exploratory investigations.

Good examples:

- compare two SDKs
- compare deployment strategies
- survey a framework or tool ecosystem

### `99.Others/`

Use only when the note does not clearly fit the other buckets.

## Choosing a `03.Projects` Folder

Pick the best destination using this order:

1. Existing folder that obviously matches the current topic
2. Existing folder that matches the current project
3. New folder named after the current project or investigation

Examples of good folder names:

- `printer-connection-issue`
- `payment-terminal-investigation`
- `customer-portal`
- `ios-print-sdk-notes`

## Choosing a File Name

Pick a file name that tells a future reader what is inside.

Examples:

- `architecture-summary.md`
- `print-flow-before-after.md`
- `failure-analysis.md`
- `handoff-notes.md`
- `sdk-behavior.md`
